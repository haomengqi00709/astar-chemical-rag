# Project Use of Standard Documents (Unmodified)

When a standard document is to be used on a project without any modifications, the project team **shall** follow a specific set of procedures to integrate it into the project documentation. This method is typically applied when the standard document perfectly aligns with project requirements and serves as a direct template or reference.

### Procedure for Unmodified Use
1.  **Commentary Removal:** The project team **shall** remove any commentary present in the standard document. This ensures that the project document is concise and focused on project-specific content.
2.  **Document Numbering:** The project team **shall** replace the prefix "Standard" with the project number. This adheres to the project's [[0-PRC-0002_document_numbering]] conventions.
3.  **Project Revision Marking:** The document **must** be marked as **Rev A or Rev 1** for the project. This establishes its initial revision within the project's document control system.
4.  **Status Indication:** The appropriate status **shall** be shown, followed by **"(S-Rx)"**, where "x" represents the revision of the originating standard document. This clearly indicates that the document is an unmodified standard (S) derived from a specific standard revision (Rx).
5.  **Revision Log:** The revision entries of the originating standard **shall** be removed from the project document's revision log. The project document will maintain its own revision history from its project Rev A or Rev 1.
6.  **Publishing:** The document **must** be published in accordance with [[0-PRC-0005_publishing_of_project_documents]].
7.  **Approval:** The document **must** be approved by the responsible Discipline Approver, as defined in [[0-PRC-2001_assignment_of_project_responsibilities]]. For documents falling under major work division 0: Administration, the responsible Discipline Approver is the Project Engineer.

This process ensures that even unmodified standard documents are properly integrated, numbered, and approved within the project's documentation framework, maintaining traceability to the original standard while conforming to project-specific administrative requirements.
