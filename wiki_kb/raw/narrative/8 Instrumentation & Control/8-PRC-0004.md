3.5. 
Process Logic Narrative 
The Process Logic Narrative will be a detailed written description of the operation and control 
of all automated equipment. It will generally contain following the elements:  
• 
Identification and locations of the control elements or devices. 
• 
Description of the specific control scheme required for the devices. 
• 
Commentaries and rationalisations as required. 
 
Process Logic Narrative will be prepared by Process. 
Process Logic Narrative will be checked by Technology. 
Process Logic Narrative will be approved by Process. 
 
3.6. 
Process Control - DCS Configuration Parameters 
The Process Control - DCS Configuration Parameters will contain the basic information needed 
for the DCS programmer to configure the basic control and monitoring elements of the control 
system. It will contain the following as minimum: 
• 
PID reference 
• 
Loop number 
• 
Loop description 
• 
Type of control or monitoring element 
• 
Scale of measurement 
• 
Units of measurement for instruments 
• 
Control action 
• 
Fail position of valves and instruments 
• 
Output 
• 
Comments 
 
Process Control - DCS Configuration Parameters will be prepared by Process. 
Process Control - DCS Configuration Parameters will be checked by Technology. 
Process Control - DCS Configuration Parameters will be approved by Process. 
 
3.7. 
Alarms, Interlocks and Setpoints 
Alarm, Interlock and Setpoints will contain process specific information needed for the DCS 
programmer to configure the control system. It will contain the following elements as applicable: 
• 
Instrument number 
• 
Description of the control element 
• 
Units of measure 
• 
Set point for normal operation 
• 
Process Instrument Alarm Set Points  (LoLo, Lo, HiHi, Hi)

Commentary 
 
To Section 3.6 (Process Logic Narrative): 
The Process Logic Narrative provides a description of all process interlocks and alarms.  The 
Logic Narrative is the primary document used for the design of the Logic Diagrams and/or the 
DCS control logic. 
 
Although the logic narrative is considered a process document, in actual practise, it becomes a 
co-joint effort between the process and control engineers. The specifics of design intent, 
feasibility and implementation dictate that a good deal of collaboration is required to craft a 
sufficiently descriptive and complete document.  Modifications, additions and deletions must be 
originated from this document. The Logic Narrative is used extensively in developing the 
operations manual. 
 
Instrumentation will check the Logic Narrative for Clarity, Simplicity and, Practicality for ease of 
configuration of a typical DCS system.  Specific interlocking and alarm requirements remain the 
responsibility of Process. 
 
To Section 3.10 (Logic Diagrams): 
Logic drawings are based on the Logic Narrative and are used in the specific configuration of 
the control system.  As such they represent the Logic Narrative in another form and are 
therefore redundant. The trend in control systems is for the software configuration (Operating 
System), to produce the control configuration documentation package.  Logic drawings will no 
longer be produced within the scope of projects. This being said, precedent may dictate 
deliverables. 
 
To Section 3.11 (Control System I/O List): 
The Control System I/O list will be prepared in conjunction with the Instrument Index by the 
Subcontractor.  A preliminary I/O list will be created during the same time frame as the 
preliminary Instrument Index.  The I/O list will include individual totals of the various types of 
I/O required for the project.  When a dual Instrument numbering system is used for the project, 
the Client’s preferred Instrument numbering will be used. 
 
The power supply identified on the I/O list will define whether the Instrument is a 4-wire type 
device or whether it is a 2-wire type device.  In addition it will define the voltage requirements of 
the individual device. 
 
Control System I/O List will contain all instrumentation and electrical devices that will be 
monitored and/or controlled directly from the plant control system.  This includes all required 
electrical monitoring signals from MCC’s, Switchgear, Transformer Rectifiers etc.  Instrument 
Tags assigned to these monitoring signals are to be shown on a P&ID. Typical Control system 
wiring will conform to the following: 
Analog inputs (2-wire/4-wire  4-20 mA) 
Discrete inputs (Isolated, Dry 120 VAC or 24 VDC) 
Discrete outputs (Isolated, High Side 120 VAC or 24 VDC) 
Digital Bus (Profibus, Fieldbus)

To Section 3.13 (Control Equipment - Cabinet Layouts and Internal Interconnection 
Wiring): 
Control Equipment drawings will show the specific special layout for Control Equipment within 
their designated cabinets.  All equipment will be identified, tagged and dimensioned. The 
drawings will identify where field devices will interface and indicate the service and type 
(Analog, Discrete, Digital). Detailed internal Interconnections will be shown in schematic and/or 
wiring format.  All interface communication connections will be shown.  Responsibility for 
supply of all communications cabling will be clearly defined. 
 
To Section 3.16 (Control System Graphics): 
Control system graphics will be laid out to provide a logical, efficient and complete interface 
between the plant operations personnel and the Control system. To reduce confusion, the 
displayed graphics for monitoring and control details will be kept to a minimum but will be 
sufficient to allow the operations personnel to completely control the process as intended. 
 
The development parameters of these graphics are somewhat subjective. The flexibility and 
expandability of state of the art systems tends to encourage imagination and personal 
preference to take a dominance over expedience. Graphics that are aesthetically appealing 
have an intangible but intrinsic appeal to clients. We want to develop graphics that are simple, 
logical and minimise frills at the same time they should be visually appealing. Within this 
environment, standardisation has become a difficult issue to deal with. 
 
To Section 3.17 (DCS Operating System Configuration): 
Due to the unique requirements and proprietary nature of Vendor Control systems, the Vendor, 
under the direction of the Instrumentation/Electrical Engineer more efficiently sets up the 
Control System Software Configuration (Operating System).  The documentation of this 
configuration is usually directly accessible from the Control system itself and will become part 
of the Control System Manual when the system is installed. 
 
To Section 3.18 (Process Control Configuration): 
The process control configuration (Application Software) will reflect the specific requirements 
for efficiently controlling and monitoring the process and will be implemented in strict 
accordance with the logic narrative and logic drawings for the project. Specific interlocks, 
alarms and trips will be implemented within the configuration as per the Instrument Set Points, 
Alarms and Interlocks section in the operating manual.
