## Introduction
The Control Function Field Checkout Procedure for Distributed Control Systems (DCS) outlines the to verify that the D Functions, have been configured and are operating in accordance with the engineering documents and specifications. The control functions are embedded in the DCS software configuration.  They include Graphic Displays, Alarm Displays, Trending Displays, Analog, Discrete and Logic Control configuration. The  specialist and the DCS programmer will perform the checks as per this procedure, with the assistance from the subcontractor as required.  On completion of this procedure the DCS is ready for water batching and commissioning.

## Sequence of Execution
DCS Hardware installed and accepted by .
Conduct the inspection of the DCS against the engineering documents and applicable procedures described later in this document, to confirm the implementation and operation is in accordance with these documents.
The DCS  control functions will be signed-off in accordance with this procedure.
Deficiencies are recorded and given to the  site supervisor/ commissioning manager.
The site supervisor/commissioning manager works with the  specialist and DCS programmer to have all the identified deficiencies corrected.

A minimum of two (2) specialists are required to facilitate the I/O testing. One specialist will be familiar with the DCS software configuration and will be located at the operators’ console for monitoring of incoming signal status and generation of outgoing signals.  The second specialist will be familiar with the field devices and will generate the required field signals at the local instruments/motor controls and monitor the final control element movements as required.
The following tests will be performed:
Analog Inputs
On the operator station, select the I/O database tag for the Analog Input  to be tested. Confirm the measurement range and engineering units. At the field located device, simulate the analog input signal as described in . These signals are witnessed at the operator station as 0, 25, 50, 75 & 100% of the range in terms of engineering units. Check alarms against Results must be listed in the appropriate columns on the DCS Configuration Checkout Sheet (8-LST-0102).
Analog Outputs
On the operator station, select the I/O database tag for the Analog Output to be tested. Confirm the measurement range and engineering units. The tag is selected to Manual Mode and the output is stepped from 0% to 100% in steps of 25% as described in . These changes are witnessed  as 4 mA, 8 mA, 12 mA , 16 mA & 20 mA steps measured at the end device  or appropriate movement of the final control element (ie: control valve). Results must be listed in the appropriate columns on the DCS Configuration Checkout Sheet 1 (8-LST-0102).
Digital Inputs
On the operator station, select the I/O database tag for the Digital Input to be tested.  At the field instrument or motor control device, bridge or open the two (2) signal wires to simulate a required closed or open contact as described in  and/or . Wherever possible, do not disconnect or bridge wires, but exercise the switching device.  This change is witnessed as a change from "0" to "1" or "1" to "0" on the object display. This procedure is repeated three (3) times. Results must be listed in the appropriate columns on the DCS Configuration Checkout Sheet 1 (8-LST-0102).
Digital Outputs
On the operator station, select the I/O database tag for the Digital Output to be tested.  The tag is selected to Manual Mode. As the value is changed from "0" to "1" (by forcing the output) and back three (3) times, changes are witnessed at the field end device using a multimeter or by observing the energisation / de-energisation of the field device as described in  and/or . Results must be listed in the appropriate columns on the DCS Configuration Checkout Sheet 1 (8-LST-0102).
On completion of all I/O testing, all I/O points must be put into their NORMAL operating mode and must be ENABLED.

## DCS Function Checkout
Drives, valves, closed loop controllers, manual loading stations and similar, graphics displays on the operator station and the logics, require checking for correct configuration.
Note: The following procedures are very time consuming and should normally be done during the FAT (Factory Acceptance Test at the DCS vendor factory).
Loop Configuration
Check correct Algorithm (P, PI or PID) if required
Check correct Action (Forward/Reverse) if required
Check Setpoint/PV tracking if required
Check Output limit if required
Check point is ENABLED
Graphic Displays
Check Graphic Links (Test all links between different graphic pages)
Check for correct graphic presentation of all objects shown on graphics
Check appearance of proper standard faceplates. (Controllers, Motors etc.)
Check correct behaviour of these standard faceplates
Logic Interlock Checkout
The programmed logic is checked against the logic diagrams. Each logic function must perform exactly as shown on the logic diagrams.
If, during this checkout the actual I/O's are not available, the complete logic can still be checked. This is done by selecting the Input Block to Mode Manual and entering an appropriate value into it while watching the output readings and/or actions.
If there was no logic checkout done at the FAT, this is to be done in the field, once all other DCS checkout has been completed. I/O manipulation/checking can be done either from the field or from the I/O Rack.
Each checked logic block will be yellowed-in on the logic diagram to indicate completed. The logic interlock checkout is complete once all the logic blocks on all the logic diagrams have been yellowed-in.

## Corrections of deficiencies
Identified deficiencies will be rectified on the spot or must be entered into the "comments" column as deemed appropriate to all parties involved at that time.
Identified and listed deficiencies must be corrected, rechecked and signed off before the complete DCS can be signed-off "Ready for water batching and commissioning".
