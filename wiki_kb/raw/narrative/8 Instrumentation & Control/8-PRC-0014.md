# 8-PRC-0014 — Procedure


[TABLE: 8-PRC-0014_table_1]


## Introduction
The Distributed Control Systems (DCS) Hardware Checkout Procedure outlines the minimum to verify that the DCS has been installed in accordance with the drawings and specifications. The DCS Manufacturer Hardware Checkout procedure(s) will form part of this document and must be used in conjunction with this document where applicable.
DCS Vendor Representative(s) will be required to perform this checkout procedure.  specialist will witness this checkout procedure.

## Sequence of Execution
During construction the site sub-contractor checks for completeness before approaching  site supervisor for the site supervisor's review.
site supervisor visually reviews the installed DCS systems against the general arrangement and installation instructions.
When the  site supervisor is satisfied that the sub-contractor has taken the work as far as can be done at that time and all hardware checkout prerequisites are complete, he notifies the Project/Commissioning Manager that the equipment is ready for a final checkout.
site supervisor/commissioning manager will advise the DCS vendor that the DCS is now ready for DCS hardware checkout.
DCS Vendor Representative(s) will verify the DCS Hardware installation against the Engineering Documents, DCS Vendor drawings and procedures, and this procedure.
DCS Vendor will provide  with a complete DCS Hardware Checkout sheet. This sheet must be completed and will be part of the DCS Hardware Checkout final document.
Deficiencies are recorded on a separate sheet and given to the  site supervisor/commissioning manager.
The site supervisor/commissioning manager works with either the DCS Vendor Representative or the subcontractor to have all the identified deficiencies corrected.
At completion of this DCS ardware heckout, the DCS will be powered and completely operational.

## Hardware Checkout
All grounding cables properly sized and terminated according to grounding drawings.
Verify the grounding meet the DCS Manufacturer Grounding Requirement(s).
All cabinet interconnect cables properly tagged, sized and terminated.
DCS communication network will be tested to ensure it meets the DCS Manufacturer’s Performance Requirement(s).

## Power-up Test
Operator Console/Engineering Stations Checkout
Power up the first Station. Observe the boot up of the station.
Check all the peripherals including CRT, keyboard, mouse, printer, horn, alarm lights, CD-ROM and other devices.
Load the station with DCS System software (if required).
Verify that the station is on-line and communicating with other DCS devices.
Check the DCS system functionality of the station.
Disconnect the communication cable and observe the station status. Ensure system alarm appears on the screen.
Repeat the same procedure on all other Operator Stations/Engineering Stations.
Highway Devices Checkout
Power up the first Highway device, wait for the self-diagnostic test to complete and observe the local status LED display (if applicable).
Disconnect the highway communication cable and observe the local status LED display.
Load the required software for this device.
Repeat the same procedure for other highway devices.

## Redundancy Test (only on redundant system)
Purpose of this test is to verify switchover to the alternate controller, power supplies, data highways and I/O modules in the event of the failure of the primary device.
Process Controllers
Force the primary controller to fail.
Observe that the switchover to the alternate controller occurs.
Observe the switch over time.
Check if the data integrity is maintained.
Check the alarms and messages on an operator station to make sure the switchover is logged complete with timestamp.
Ensure the current controller operate stable for a minimum of two minutes.
Repeat the same procedures above to make sure the controller switches over to the original controller.
Data Control Network
Disconnect one of the data .
Verify the alarm messages on operator consoles.
Verify the uninterrupted operation of all outputs.
Verify the event is logged.
Repeat the same procedure on the alternate data
DCS Power Supplies
Turn off one of the power supplies.
Observe alarm message appears on the operator station.
Check the controller and I/O modules status.
Repeat the same procedure for the alternate power supplies.

## System Integrity Test ( for non-redundant system)
Purpose of this test is to verify the database, logic, analog functions, and all I/O configurations are maintained on failure of a non-redundant controller.
Process Controller and I/O modules
Fail the controller or I/O module.
Check the alarm messages on operator consoles.
Leave the controller or I/O module out of service for a minimum of one hour.
Return the controller or I/O module back to service.
Check all system configuration, logic and functions; observe the I/O status.
Observe all alarm messages are cleared.
