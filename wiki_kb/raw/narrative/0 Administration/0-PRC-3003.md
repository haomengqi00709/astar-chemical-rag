# 0-PRC-3003 — Procedure


[TABLE: 0-PRC-3003_table_1]


## Purpose
This procedure describes the methods by which project home-office resources are monitored to provide measures of progress and productivity and forecasts of ongoing requirements.

## Project Resource Management System
The Project Resource Management System (PRMS) is a Microsoft Excel spreadsheet that provides the required functionality and reporting facilities.
The body of this procedure provides a generalised description of the functioning of the PRMS. Additional detailed operating instructions are appended.
Project Controls inputs all data to the PRMS, and produces all reports from it.

## Project Design Resources

### Structure
The PRMS contains one worksheet for each cost code between ENG-0-5000 and ENG-9-9200.
The work of each cost code is broken down into discrete activities corresponding to specific document deliverables or discrete milestones.
Each activity is assigned a value of unit earned hours for each department that participates in the execution of that activity.

### Project Scope
The base configuration of the PRMS is for a full EPC project. In the case of a project of less design scope the PRMS must be re-configured to suit. This is done by “toggling off” all activities that are not included in the project design scope.

### Quantification
Each cost code is assigned standard quantification units.
For example, for cost code ENG-4-1000 Type A Equipment, the unit of quantification is the count of unique equipment items. The tag number and description of each unique equipment item is entered into the rows of worksheet ENG-4-1000 with an assigned quantity of 1.
In cases where the count of completed activities is derived from some other system then only a single item is entered into the cost code worksheet with the total count of items entered as the quantity.
Updating of quantities is achieved by ensuring that all items are entered into the cost code worksheet, or that the quantity entered is correct.

### Budget
The estimated (budget) quantity of items for each cost code is entered into the PRMS, and may not be changed except as authorised by a Change Notice (0-PRC-4003: Scope Change Control).
The budget hours are then derived from the budget quantity of items for each cost code, multiplied by the assigned values of unit earned hours for each department for each cost code.

### Work Status
In the case of quantification with one item per worksheet row, the work status for each activity is either zero, or unity when the work of the activity is fully completed.
In the case where quantification is grouped, then the work status for each activity is the actual count of items for which the work of the activity is fully completed.

### Earned Hours
Totals of earned hours are calculated for each department for each cost code. These totals of earned hours are calculated from the value of unit earned hours for each department each activity.
The values of unit earned hours are calculated by dividing base unit  by the assumed productivity for each department.

### Actual Hours
Actual hours expended are transferred manually from the accounting database into the PRMS cost code worksheets as totals per department “to date”. The time-based functionality of the PRMS therefore relies on input of actual hours at regular intervals.

### Productivity
Productivity is defined as earned hours divided by actual hours, therefore a productivity of less than unity reflects worse than average performance, and a productivity of greater than unity reflects better than average performance.
Productivity is calculated for each department for each cost code.

### Assumed Productivity
In preparing the estimate (budget), assumed productivity for each department is entered into the PRMS in anticipation of better or worse than historic average performance of the design work.

### Forecast Hours
A forecast of actual total hours for each department for each cost code is calculated by dividing the forecast earned hours by the productivity. Forecast earned hours are calculated based on the actual quantities entered.

### Progress
Progress is defined as earned hours divided by forecast earned hours (%).
Progress is calculated for each department for each cost code.

### Project Design Totals
The data of each cost code worksheet is totalled onto a single worksheet

## Project Overhead Resources

### Structure
The PRMS contains a single worksheet for cost codes ENG-0-0100 to ENG-0-4400.

### Budget
The budget for the total of the overhead cost codes is entered into the worksheet, distributed across each department.

### Actual Hours
Actual hours expended for the total of the overhead cost codes is transferred manually from the accounting database into the PRMS overhead worksheet as totals per department “to date”.

### Productivity
Productivity for each department’s total of the overhead cost codes are set identical to the value calculated for that department’s design work.

### Forecast Hours
Forecast hours are calculated for each department’s total of the overhead cost codes using the budgeted hours and the assigned values for productivity.

## Updating
The PRMS will be updated at regular intervals as set out in 0-PRC-2002: Project Instructions. The updating requires the following inputs:
Import actual hours expended as totals per department “to date”.
Show latest actual quantities of items on the cost code worksheets.
Show latest status of each activity for each item on the cost code worksheets.
Adjust budget quantities of items on the cost code worksheets per any Change Notices.
Adjust budget hours by adjusting the assumed productivity for each department per any Change Notices.
The status and quantity data are provided to Project Controls by the Project Engineer and the Discipline Leads.

## Resource Forecasts
The PRMS contains a single worksheet for resource forecasting.
This worksheet stores a time-based record of total actual hours. At the time of an update the total forecast hours for each department are transferred in and the hours to go are manually distributed over the remaining duration of the project, giving consideration to the requirements of 0-DAT-3001 Project Schedule.
The details of this worksheet are made available to the Project Engineer, the Discipline Leads, and the department heads to assist them in resource planning and project assignments.
A record is kept on the resource forecast worksheet of the first such distribution of resource requirements. This is the budget distribution used as a reference.

## Instructions

### Initial Input
Estimating
In order to obtain an office hours estimate PRMS must be updated with project specific data input manually in all cells where the values are in blue. Following this input PRMS must be manipulated to define project scope and to tune up the final estimate. The inputs and manipulations should be made in the following order:
“Totals” Worksheet:
Enter project name and number.
“Est-budget” Worksheet:
Unprotect the sheet and define all quantities of work objects for cost codes between ENG-0-5000 and ENG-9-9200.  Fill up estimate of administration hours for codes from ENG-0-0100 to ENG-0-4400. Protect the worksheet without a password.
Cost Code Worksheets:
If the project is a full EPC job this step may be omitted. For projects with limited scope change  “y” to “n” in row 87 for activities which are not included. See commentary.
Open up “admin” worksheet and distribute administration budgeted hours between disciplines. The total of budgeted hours for this worksheet must agree with the estimates on the “Est-budget” worksheet.
“Tune-up” Worksheet:
On the “Totals” sheet check if the budget for each discipline is reasonable for this project. If not the PRMS requires tune-up. Open up and unprotect the “Tune-up” worksheet. Adjust the assumed productivity factor such that your budget on the “Totals” page matches your expectation. When done protect the “tune-up” sheet without a password.  Note that the assumed productivity factor multiplies the calculated (sheets ENG-0-5000 to ENG-9-9200) hours only. It does not multiply administration hours, which have been input manually.
Project Execution
At the onset of the project the master copy of PRMS has to be populated with project specific data. The initial project specific data will be input manually in all cells where the values are in green.  To prepare the initial input the following information is required:
basic procurement plan (list of expected PO’s)
equipment list, instrument list, electrical equipment list
documents list
simple project schedule
The initial inputs should be made in the following order:
“Totals” Worksheet:
Enter the current date.
Cost Code Worksheets:
Fill out each worksheet with “work objects” (these are mostly the deliverables).
Open up “admin” worksheet and distribute administration budgeted hours between disciplines.
“EMF” Worksheet:
Unprotect the EMF work sheet and unhide column F. Input dates in weekly intervals at the top of the EMF (row 5). Distribute in time budgeted hours for each department. Sum of the distribution (column F) must equal to the budgeted hours for the department (column E). When done, protect the worksheet again.

### Regular Updating
Updated data will be input manually in all cells where the values are in red.
To do the update the following information is required:
Knowledge of the current status of all work objects - done/not done  (or 1/0) status.
Actual hours spent by each discipline for each cost code.
Knowledge of new, previously unaccounted for quantities of work objects.
To update the PRMS first open the last PRMS workbook. The update should be made in the following order:
“Totals” Worksheet:
Enter the current date.
Cost Code Worksheets:
Fill out each worksheet with actual hours spent by each department until the date of the update.
For each work object change 0 to 1 for activities completed. Treat activities that are partially completed as 0.
“EMF” Worksheet:
At the bottom of the worksheet enter the accumulated actual hours (row 62) for the current and past dates and accumulated earned hours (row 64) for the current and past dates.
“S-Curve” Worksheet:
For Actual and Earned graphs increase data range to include the last data entered on the “EMF” worksheet
During the update all worksheets should remain protected.

### Reports
After each update print the “Totals”, “Budget”, “admin” and the “S-curve” worksheets. These should be appended to the Project Manager’s monthly report. The EMF worksheet should be used to inform the department managers about project manpower requirements. For this purpose print the forecast from the current date on – do not print past forecasts.

## Dealing with Change
If new work object quantities have been added/removed to/from the project, the new quantities should be entered on “Est-budget” worksheet. The worksheet will calculate the change to the budget required for delivery of these new quantities. In essence follow the procedure described in section 1.1-Estimating, of this specification.

## Storing
All projects should use the PRMS and update it regularly. During project execution all PRMS workbooks should be kept in the same place on the P:\ drive. This will allow for easy collection of manpower requirement forecasts for all projects to feed them to a company wide manpower level management system.
Locate your last PRMS update in p:\00\0admin\3planning\progress\current. Keep previous updates of PRMS in p:\00\0admin\3planning\progress\archives or delete them keeping only hard copies of “Totals”, “Est- budget”, “S-curve”, “Tune up” and “EMF” worksheets.
